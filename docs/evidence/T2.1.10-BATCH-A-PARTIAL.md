## 4. Open blockers

### 4.1 Play missing-file guard — backend dependency

Confirmed absent after recon:
- `packages/shared/src/index.ts` → `TrackSummary` has no `file_exists`,
  `file_missing`, or equivalent status field.
- `apps/desktop/src-tauri/src/commands.rs` → no file-existence / stat / check command.
- `PreviewPlayer` does not expose a file-existence or file-error state to the library.

Consequence: `playDisabled` is currently hardcoded `false` in `App.tsx:3234`, with
`playDisabledReason={undefined}` at `App.tsx:3235`. The component already accepts
both props and renders the reason as a tooltip (`RowContextMenu.tsx:165-166`), so
the UI half is ready and the caller supplies no signal. Play is therefore always
enabled, even for a missing file. **This is a known spec gap, not a passed check.**

Required prerequisite (separate task, approve before implementing):
- Add a file-availability signal — either a computed field on `TrackSummary`
  populated during indexing/scan, or an on-demand existence command.
- Prefer an indexed status field over per-row synchronous filesystem calls.
- Then derive `playDisabled` + a redacted, user-facing reason in the menu.
- **Do not substitute a hardcoded `false` or a "future wiring" prop stub.**

### 4.2 Component test harness — infrastructure gap

Answered with evidence, not assumption:

- **Which runner does `pnpm --filter @dj-assistant/desktop test` use?**
  `apps/desktop/package.json:14` → `node --test "src/**/*.test.ts"`. It is **Node's
  built-in test runner, not Vitest** — despite AGENTS.md describing front-end tests
  as Vitest (that claim is stale).
- **Why the 7 placeholders are invisible:** the glob matches `.test.ts` only, which
  does **not** match `RowContextMenu.test.tsx`. The file is never collected, so the
  count stayed 154 instead of rising to 161. An explicit glob that matches no files
  exits 0 with `tests 0` — this fails **silently**, not loudly.
- **Do existing tests cover any React component?** No. Coverage is pure logic only
  (`ui-state.ts`, `library.ts`, `logging.ts`, `library-columns.ts`), all `.test.ts`.
- **Is `@testing-library/react` + a DOM environment already a dev dependency?**
  **No.** Grepping root, `apps/desktop`, `packages/*` and `apps/api` package.json
  files returns zero matches for `vitest`, `jsdom` or `@testing-library`.
- **Smallest approved change to enable component tests:** widening the glob alone is
  not enough — `node --test` cannot transpile JSX, and rendering needs a DOM. The
  minimum is a transpiled runner plus DOM plus a React library: **Vitest +
  `@testing-library/react` + `jsdom`** (three new devDependencies, plus config).
  Node 24 is the runtime (`v24.22.1` on this box).

**No new Playwright suite.** Any harness change is a separate, explicitly
approved task — not a drive-by refactor inside T2.1.10. Until that task lands, the
committed placeholder file is dead code: it satisfies neither DoD 6 nor DoD 7 and
must not be cited as test coverage.
